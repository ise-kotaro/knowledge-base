# Recording Knowledge

## Overview

調べて理解したことを、個人の知識ベースにMarkdown + HTMLで蓄積する。
コアの原則は2つ：

- **同じことを二度調べない** — 保存前に必ず既存ノートを探し、新規作成・追記・補足のどれかを判断する
- **記録するコードは動く状態にする** — 実行確認していないコードを残さない

## 知識ベースの場所

1. プロジェクトの `CLAUDE.md` / `AGENTS.md` に「Knowledge base」または「知識ベース」の記載があればそこを使う
2. なければ `~/.claude/CLAUDE.md` の記載を見る
3. どちらにもなければ `~/Documents/knowledge-base` をデフォルトとする

## 手順

### 1. 既存ノートを探す

```bash
# INDEX.md を読む（存在すれば）
cat <知識ベース>/INDEX.md

# 本文・タグをgrep
rg -i "キーワード1|キーワード2" <知識ベース> --glob "*.md"
```

キーワードは日本語・英語の表記揺れ（例: Entra ID / EntraID / Microsoft Entra）も網羅する。ヒットしたノートは**必ず全文読む**。

### 2. 保存方針を決める

| 状況 | 対応 |
|---|---|
| 同じテーマのノートがある | そのノートにセクションを**追記**し、`updated` を今日に更新 |
| 関連するが別テーマ | **新規ノート**を作り、互いの `related` に相互リンクを追加 |
| 完全に新規 | **新規ノート**作成 |

### 3. ノートのディレクトリを切る

**1ノート = 1ディレクトリ。** `YYYY-MM-DD-英語スラッグ/`（例: `2026-08-20-msal-token/`）を作り、本文・コード・生成物はすべてこの中に置く：

```
2026-08-20-msal-token/
├── README.md        # ノート本文（日本語）
├── README-en.md     # 英語版（任意）
├── index.html       # README.md から生成
├── index-en.html    # README-en.md から生成
├── main.py          # サンプルコード
└── requirements.txt # 依存（必要な場合）
```

コードが絡む場合は、**実行して動作確認したコードだけを記録する**：

1. コードを実ファイルとしてノートのディレクトリ内に置く
2. 実行環境を用意し、実際に動かして確認する：
   - 標準ライブラリのみ → そのまま実行
   - 外部パッケージ → 知識ベース直下の共有 `.venv` を使う（なければ `python3 -m venv .venv` で作成）。依存はノートのディレクトリの `requirements.txt` に残す
   - DB等の外部サービスやランタイムのバージョン固定が必要 → `Dockerfile` / `compose.yml` をノートのディレクトリに置き、コンテナで実行確認
3. シークレットは直書きせず環境変数から読む形にし、必要な環境変数を実行手順に明記する
4. 実行手順はノート本文の「サンプルコード」セクションに書く

### 4. Markdownノートを書く

- 本文はノートのディレクトリ内の `README.md`（英語版は `README-en.md`）
- テンプレート: `templates/note.md`（日本語）/ `templates/note-en.md`（英語）
- サンプルコードは要点をコードブロックで抜粋し、完全版は同じディレクトリ内のコードファイルを指す
- 出典（公式ドキュメント等のURL）があれば「出典」セクションに記載
- Markdownは変換スクリプトが対応する記法に留める（見出し・リスト・表・コード・リンク・引用・太字斜体・脚注 `[^n]`）

### 5. HTMLに変換する

```bash
python3 <このスキルのディレクトリ>/md2html.py <ノートdir>/README.md
```

`README.md` → `index.html`、`README-en.md` → `index-en.html` に変換される。ノート更新時も再実行する。

### 6. INDEX.md を更新する

`<知識ベース>/INDEX.md` の表に1行追加/更新。ファイル列には**ディレクトリ名**を書く：

```
| 日付 | タイトル | タグ | ファイル |
```

`related` を追加した場合は**相手側ノートにも逆リンクを追記**し、HTMLを再生成する。

### 7. 報告する

作成/更新したファイルパスと、取った方針（新規・追記・補足）を一文でユーザーに伝える。

## 文体・ライティング

ノート本文は、状況に応じて次のライティングスキルに必ず従って書く。書き上げたら各スキルの点検手順をセルフチェックで回す。

| 状況 | 使うスキル |
|---|---|
| 日本語のノート | **japanese-tech-writing**（必須） |
| 読み物として読ませたい長い解説 | 上記に加えて **cognitive-rhythm-writing** |
| 英語のノート | **english-tech-writing** |

- 言語はユーザーの依頼で決める。指定がなければ日本語
- 英語版も作る場合は同じディレクトリに `README-en.md` として作り、日英で互いを `related` に入れて相互リンクする

## Common Mistakes

- **既存ノートを読まずに新規作成する** → INDEX.md + grep は必須。怠慢すると二度手間の元になる
- **ライティングスキルを参照せずに書く** → 日本語は japanese-tech-writing、英語は english-tech-writing に必ず従う
- **実行していないコードを載せる** → 必ず動作確認してから。嘘コードは知識ベースの信頼を壊す
- **追記後にHTML再生成を忘れる** → MDとHTMLが不整合になる
- **シークレットをコードに直書きする** → 環境変数から読む形にする
- **知識ベース外（プロジェクト内など）に書く** → 必ず設定された知識ベースに保存する
